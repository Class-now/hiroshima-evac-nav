# PLATEAU AWARD 2026 一般部門 スライド構成案

- 作品名: 広島 3D 多言語避難ナビ
- 公開 URL: https://class-now.github.io/hiroshima-evac-nav/
- 想定: 12/5・6 のオンライン審査（動作デモ）の前後に画面共有で使う。10〜11 枚、1 枚 30〜60 秒。
- 方針: 「説明より実物」。スライドは問い→答え→実演への橋渡しに絞り、文字は少なく。
- 禁止事項: 利用者数・効果の数値・体験談を作らない。必要な箇所は【要記入】のまま残す。

## 1. タイトル

- **伝えること**: 何のアプリか一文で。
- **画面/図の案**: 中区の 3D 建物が浸水深で色分けされたスクリーンショットを全面に。右下に QR（公開 URL）。
- **話す要点**
  - 「この建物の何階まで水が来るか」を、旅行者・留学生にも分かる言葉で示す Web アプリ
  - PLATEAU 広島市 2024 の 3D 都市モデル × 県の防災データ（DoboX）
  - 大学 2 年生の個人開発

## 2. 課題 — ハザードマップは「平面」で「日本語」

- **伝えること**: 既存のハザードマップでは「今いる建物でどう動くか」が分かりにくい。外国人や土地勘のない人ほど困る。
- **画面/図の案**: 左に平面の浸水想定図（イメージ）、右に「?」を浮かべた建物の 3D。
- **話す要点**
  - 平面図は「この地点が何 m」まで。「この建物の何階なら安全か」は自分で考える必要がある
  - 広島市中心部は観光客・留学生・外国人住民が多い（【要記入: 引用する公的統計があれば出典つきで。なければ削除】）
  - 着想のきっかけ: 【要記入: 本人の体験（例: 外国語専攻として感じたこと）】

## 3. 答え — 建物をタップすると「何階より上へ」

- **伝えること**: 中核の体験。タップ 1 回で判断材料が出る。
- **画面/図の案**: 建物タップ → 下部シートに「水の高さ 約 X m／水が引くまで 約 Y 時間／この建物 N 階建て／N 階より上へ」。実演の GIF でも可（数値は実画面のものを使う）。
- **話す要点**
  - 建物属性の浸水深（L2 想定最大規模の最大値）・浸水継続時間・地上階数を読む
  - 浸水深から「安全な階」を出し、建物の階数と比べて「上の階へ」か「避難場所へ」かを示す
  - 階数属性がない建物は計測高さから推定し、推定であることを明示

## 4. 3D 都市モデルで「街全体」を一目で

- **伝えること**: 色分け 2 モードで、個別建物だけでなく街の傾向が見える。
- **画面/図の案**: 同じ視点で 2 枚並べる。左「浸水深の色」（手引きの凡例色）、右「上の階へ逃げられる建物」（緑／赤）。
- **話す要点**
  - 浸水深モード: 水害ハザードマップ作成の手引きの凡例色で建物を塗る
  - 逃げられる建物モード: 建物ごとに「浸水深に対して階数が足りるか」を判定して緑／赤
  - 平面図では表現できない「高さ」の情報を、PLATEAU の建物属性から直接引き出している

## 5. 災害の種類ごとに切り替え

- **伝えること**: 洪水だけでなく高潮・津波・土砂災害に対応。避難場所も災害種別で絞る。
- **画面/図の案**: 災害切替ボタン（洪水・高潮・津波・土砂）と、それぞれの浸水想定区域／警戒区域の表示例を 4 分割。
- **話す要点**
  - 洪水: 太田川・元安川・天満川・旧太田川・京橋川・猿猴川の 6 河川の L2 浸水想定区域
  - 高潮・津波: PLATEAU の浸水想定区域
  - 土砂: DoboX の土砂災害警戒区域（中・東・南・西区 843 区域）
  - 最寄り避難場所は「その災害に使える場所」だけから 3 件、方角と直線距離で表示

## 6. 4 言語 ＋ やさしい日本語

- **伝えること**: 言葉の壁を下げる工夫。機械翻訳で固有名詞を作らない方針。
- **画面/図の案**: 同じ建物の結果画面を 4 言語で 2×2 に並べる。
- **話す要点**
  - やさしい日本語・English・简体中文・한국어。URL の ?lang= で直接開ける
  - 避難場所名はローマ字＋施設種別（例: 小学校 → elementary school）で示し、施設名を機械翻訳しない
  - 路面電車の電停名は事業者の公開データ（GTFS）の訳を優先、無いものは作者が作成
  - UI の訳語は作者が確認（【要記入: 確認の範囲・協力者がいれば了承を得た上で】）

## 7. 「今」の川の状況 — DoboX 河川水位

- **伝えること**: 想定（PLATEAU）に、観測（DoboX）を重ねる。
- **画面/図の案**: 地図上の水位観測所マーカーと、タップ時の「最新水位／基準水位との比較」吹き出し。
- **話す要点**
  - DoboX の観測所一覧と水位日集計 CSV を毎日取り込み（日本国内のマシンで定期実行。DoboX は国外から接続できない）
  - 観測所ごとに最新水位と基準水位を比べて地図に表示
  - 対象観測所数: 【要記入: 実装後の件数】
  - 日集計のため「リアルタイムではない」ことを画面にも明記

## 8. 迷わせない UI

- **伝えること**: 初めての人が 30 秒で使える設計。
- **画面/図の案**: スマホ幅の画面 3 枚（初回の使い方案内 → 凡例 → レイヤー切替）。
- **話す要点**
  - 初回だけ使い方案内、凡例は常に画面に
  - レイヤー切替（建物・浸水区域・土砂・避難場所・電停）
  - スマホ幅でも操作が完結。現在地 or 地図の中心から最寄りを探す
  - 「これは予測です。広島市の情報に従ってください」の注意書きを常時表示

## 9. 技術 — ビルドなし・サーバーなし・外部 API なし

- **伝えること**: 小さく作って、壊れにくく、誰でも動かせる。
- **画面/図の案**: 構成図。
  ```
  PLATEAU 配信(3D Tiles) ──┐
  地理院タイル ─────────────┼─> CesiumJS (CDN, ビルドなし) ─> GitHub Pages
  data/*.geojson (同梱) ────┘          ▲
     ▲                                  │
  scripts/build_data.py           scripts/build_river.py（毎日: DoboX 河川水位）
  (DoboX・国土地理院・国土数値情報)  Playwright スモークテスト
  ```
- **話す要点**
  - CesiumJS を CDN から読み、PLATEAU の 3D Tiles を直接ストリーミング（Cesium ion 不使用）
  - ジオイド高を補正して 3D Tiles と地面の高さを合わせた
  - 元サーバーに CORS が無いデータは Python（標準ライブラリのみ）で事前に GeoJSON 化して同梱
  - 最寄り計算・方角はブラウザ内で計算。外部 API に依存しない
  - Playwright の自動スモークテストで、表示・言語切替・建物選択を確認

## 10. 限界と次の一歩

- **伝えること**: できないことを正直に。
- **画面/図の案**: 箇条書きのみ。
- **話す要点**
  - 浸水深は想定最大規模の予測値。実際の避難判断は広島市の発表に従う
  - 避難場所までは直線距離。道路の通行可否は考慮していない
  - 河川水位は日集計で、リアルタイム警報の代わりにはならない
  - 対象は広島市の中・東・南・西区

## データ出典（スライド 11 または末尾に掲載）
